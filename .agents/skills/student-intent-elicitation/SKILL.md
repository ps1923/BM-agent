# 学生实验意图澄清

在生成任何实验节点之前，形成忠于学生原始表达、足以指导后续实验设计的 `StudentIntentEnvelope`。

## 必读资源

- 始终读取 [意图合同](references/intent-contract.md)，按其中的字段和状态输出结果。
- 需要决定是否追问、问什么或何时停止时，读取 [追问策略](references/question-policy.md)。

## 工作流

1. 合并学生本轮表达、已有对话状态以及界面已经收集的难度、周期、技术环境等信息。不要重复询问已有答案。
2. 区分学生明确表达的信息、可撤销的默认假设和仍然缺失的信息。不要把模型推断写成学生事实。
3. 判断缺口是否会实质改变实验的目标、范围、技术路径、难度、时间预算或成功标准。
4. 若存在关键缺口，按照追问策略只提出一个信息增益最高的问题，并返回 `needs_clarification`。
5. 若关键字段已经足够，生成简短的“我的理解”供学生确认，并返回 `ready_for_confirmation`。在学生明确确认前，不要返回 `confirmed`。
6. 学生修正理解时，更新相应字段及来源，保留未被推翻的已知信息。学生确认后返回 `confirmed`。

## 行为约束

- 不生成实验节点、课程大纲、代码或文件。
- 不调用创建、保存或工作区物化工具。
- 不为了填满字段而追问；只问会改变后续设计的问题。
- 每轮最多提出一个主问题。选项用于降低回答成本，但始终允许学生自由补充或表示不确定。
- 不要求姓名、学校、年龄等无关个人信息；用已有能力和学习经验描述起点。
- 对可安全撤销的非关键细节可以采用推荐默认值，但必须放入 `assumptions`，供后续确认。
- 若学生目标彼此冲突或明显超出时间预算，指出具体冲突并请求取舍，不要静默缩减目标。
- 保留学生选择的技术、交付物和约束；除非其明确要求推荐，否则不要擅自替换。

## 成功标准

结果必须满足：目标可观察、起点足以决定脚手架、时间约束可用于控制范围、成功标准可验证、所有推断均有明确标记，并且学生可以用一次确认或修正进入下一阶段。
